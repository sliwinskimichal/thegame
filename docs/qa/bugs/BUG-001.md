# BUG-001 — Laboratorium po cichu renderuje inny styl/scenariusz przy nieznanym id; turniej może podpisać cudzy render

| Pole | Wartość |
|---|---|
| Typ | błąd (narzędzia turniejowe) |
| Priorytet / waga | **P2 — wysoki** (integralność turnieju nr 3 = decyzja M1) |
| Obszar · KM | `src/lab/main.ts`, `scripts/tournament.mjs` · M1 |
| Właściciel poprawki | engine-graphics-programmer (lab), tools-programmer (tournament.mjs) |
| Środowisko | commit 2d29211 i 2b63f08; Chromium (Playwright 1.63, globalny) + ANGLE/SwiftShader; `vite --port 5174` |
| Częstość | 100% |
| Dowód | `tests/qa/lab-audit.mjs` (sonda `__no_such_style__`): `/tmp/underhearth-qa/lab-audit/audit.json`, `/tmp/underhearth-qa/ill-audit/audit.json` |

## Warunki początkowe
Serwer laboratorium działa (`http://localhost:5174`), dowolny styl zarejestrowany w `src/lab/styles/index.ts`.

## Kroki odtworzenia
1. Otwórz `http://localhost:5174/lab.html?hud=0&style=__no_such_style__&scenario=cave`.
2. W konsoli: `window.__lab.style` → `"s01-diorama"`; brak błędu i ostrzeżenia w konsoli.
3. Otwórz `lab.html?style=r2b-silhouette-plus&scenario=jaskinia` (literówka w scenariuszu) → kadr `overview`, bez komunikatu.
4. `await __lab.setScenario('nie-ma')` → kamera zostaje w poprzednim scenariuszu, obietnica się rozwiązuje.
5. `node scripts/tournament.mjs http://localhost:5174 /tmp/t s01-diorama,s1O-typo` → katalog `s1O-typo/` zawiera rendery S01, `manifest.json` zapisuje `id: "s01-diorama"` pod kluczem `s1O-typo`, skrypt kończy się sukcesem.

## Oczekiwane
Nieznany `style`/`scenario`/`mat` (mat już rzuca wyjątek) kończy uruchomienie błędem widocznym w konsoli i w `__lab` (np. `__lab.error`), a `tournament.mjs` przerywa wpis (lub cały przebieg), gdy `__lab.style !== żądany id`.

## Faktyczne
`STYLES.find(...) ?? STYLES[0]` i `SCEN.find(...) ?? SCEN[0]` w `main.ts` — cichy fallback; `tournament.mjs` czyta `__lab.style`, ale go nie porównuje. To samo w harnessie QA (`?style=__no_such_style__` → `i01-outline`).

## Wpływ
Literówka lub usunięty/przemianowany wariant (agent grafiki dodaje i zmienia warianty w trakcie turnieju — `i11` zniknął, `i13` pojawił się w trakcie audytu) daje planszę, na której wariant „X” jest w rzeczywistości S01/i01. Metryki (`metrics.py`, `refstats.py`) i ocena trafiają do złego wariantu → błędna decyzja kierunku artystycznego M1. Nie dotyczy gracza.

## Weryfikacja poprawki
- `node tests/qa/lab-audit.mjs` — wiersz `__no_such_style__` ma `gotowy: NIE` (albo błąd), a nie „(fallback)”.
- Turniej z celowo błędnym id kończy się kodem ≠ 0 i nie tworzy katalogu wariantu.
- `__lab.setScenario('nie-ma')` odrzuca obietnicę.

## Regresja
Wszystkie istniejące wywołania z poprawnymi id (15 stylów areny, galeria, `&flood=1`, `&mat=`), domyślny styl przy braku parametru `style` (dziś: pierwszy z rejestru — zachować albo udokumentować), `scripts/shot.mjs`.
